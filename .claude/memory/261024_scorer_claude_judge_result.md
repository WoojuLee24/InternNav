# 채점기 검증 확장 + Claude 채점기 시험 — 2026-10-24 KST

## 용어
- 오경보 = 원문(맞는 문장)을 틀렸다고 함. 사람 문장에는 진짜 실수도 섞여 있다
- 검출률 = 일부러 틀리게 고친 문장을 잡음
- 방-집 = 이 집에 있지만 경로에 없는 방에서 멈춘다고 고침 / 방-지남 = 경로에서 지나온 방(끝 방 아님)에서 멈춘다고 고침

## 코드 (prompt_opt/)
- `check_mutations.py`: 오답 시험. 틀리게 고치는 표현은 채점기 정규식과 따로 만든 목록(회전 14·계단 20·멈춤 10). `--forms` 표현별, `--turn-min-deg` 회전 목록 하한 비교
- `claude_judge.py`: `claude -p --model claude-opus-5-5 --effort medium --safe-mode --tools "" --system-prompt <채점 지시>` 로 10문장씩 채점. 경로 사실 = 출발 회전·회전(그 자리 방)·계단·들어가는 방·끝 방을 순서대로 (`route_events`)

## GEPA 채점기에 연결 (기본 = gemma 1+2)
- `configs/gepa.yaml`: `score.fact_checker: gemma` (기본), `fact_checkers:` 이름별 설정 — rule, gemma, gemma_noverify, sonnet, sonnet_noverify, haiku, opus. `fact_checker` 항목이 없으면 rule (v1 과 같음)
- `prompt_opt/fact_judge.py` (새 파일): 모델 사실 검사 (경로 사실 v1/v2, 1단계 찾기, verify 면 2단계 다시 따지기, 답에서 빠진 문장은 한 문장씩 최대 2번 다시 물음). `claude_judge.py` 도 이 모듈을 씀
- `scorer.py`: `score_paths(..., checker=None)` — rule 이면 예전 계산 그대로(`_rule_issues`), model 이면 `_model_issues` (모델 지적 + 규칙의 최소 정보 검사). 점수·피드백 조립은 `_assemble` 로 공용
- `run_gepa.py --fact-checker <이름>`, `check_scorer.py --fact-checker <이름>`, `adapter.NavLabelAdapter(..., fact_checker=None)`. seed.json 에 `_fact_checker` 기록
- 검증: `check_scorer.py --labels b1 --fact-checker rule` 출력 jsonl 3개가 변경 전과 바이트 동일. 기본(gemma): 사람 오경보 20.5 %, b1 12.9 %, left↔right 뒤집음 70.6 % (분모 303 전체), 답 못 받은 문장 0~1/303. Sonnet 경로 20문장 시험 정상. `run_gepa.py --run smoke_fc --smoke` 정상 (seed.json `_fact_checker: gemma`)
