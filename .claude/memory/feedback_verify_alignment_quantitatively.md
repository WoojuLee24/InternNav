# 정합/오프셋 문제는 절대 눈으로만 판단하지 않는다

이미지·기하 정합(pose, depth, intrinsic 등) 문제를 의심할 때는 시각적으로 "맞아 보인다/틀려
보인다"로 결론짓지 않는다. `cv2.matchTemplate`로 픽셀 오프셋을 직접 재거나, 후보 변환(순서·부호·
±0.5px 등)을 브루트포스로 다 시도해 실측 오차(MAE 등)로 순위를 매긴다.

**Why**: gs_vlnpe 파이프라인에서 이 원칙으로 실제 버그 두 개를 잡았다(2026-08-04,
[[260804_gs_vlnpe_04_render_obs_result]]) — ① depth가 "픽셀만큼 밀려 보인다"는 지적에 대해
단순 `np.roll` 오프셋 스캔은 매끈한 depth 평면에서 변별력이 없어 결론이 안 났지만, intrinsics의
cx/cy에 ±0.5px 조합 6가지를 실제로 렌더링에 넣어 MAE를 재보니 `+0.5,+0.5`에서만 0.0074→0.00005로
붕괴 — Open3D `set_projection`의 픽셀 모서리/중심 컨벤션 차이라는 확정적 증거를 얻었다. ②
"render가 더 어둡다"도 평균 밝기를 실측하고 조명 인텐시티를 스윕해서 정량적으로 맞는 값(270000)을
찾았다.

**How to apply**: 픽셀 오프셋 의심 시 (a) 후보 변환/오프셋을 전부 브루트포스로 나열, (b) 각각
실측 오차(MAE, matchTemplate score 등)로 채점, (c) 매끈한/저텍스처 신호(빈 벽, depth 평면 등)는
변별력이 낮으니 "이 지표 차이가 노이즈 수준인지" 먼저 확인(비슷한 값들끼리는 결론 내리지 않음).
밝기/노출 문제는 평균 픽셀값 같은 스칼라 지표를 실측하고 파라미터를 스윕해서 맞춘다 — "조금 어두운
것 같다"는 느낌만으로 조명 값을 임의로 올리지 않는다.
