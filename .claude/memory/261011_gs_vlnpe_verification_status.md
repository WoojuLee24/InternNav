## 남은 것 — 노은역 rgb 전후 대조 (약 35분)

depth·경로·`camera_config`·parquet·meta는 **모든 조건에서 바이트 동일**이 확인됐다.
rgb만 미결인데, **비교 방법이 잘못돼서** 결론을 못 냈다.

```
bash /tmp/ab_render.sh     # 스크립트는 그대로 있다. 없으면 아래 절차대로 재작성
```

### 재개 절차
1. GPU가 비었는지 확인: `nvidia-smi --query-compute-apps=pid,used_memory --format=csv,noheader`
2. **수정 전 코드**(worktree `/tmp/pre_abc`, 커밋 `2e65f4f`)로 1ep 렌더
3. 285프레임이 나오는 즉시 **PID로 kill** (`close()`를 기다리지 않는다)
4. **수정 후 코드**(`/ws/src/InternNav`)로 같은 명령
5. rgb 285장 바이트 비교

## 이번에 알아낸 렌더러 성질 (중요)

**① 렌더러 rgb는 세션마다 미세하게 달라진다 — depth는 안 그렇다.**

| 두 실행 | rgb 바이트 동일 |
|---|---|
| 연달아 돌린 쌍 (`rt_before`↔`rt_after`, `Y`↔`Y2`) | **285/285** |
| 몇 시간 간격 + 사이에 다른 Isaac 실행 다수 | **0/285** (평균차 0.7/255) |

→ **전후 비교는 반드시 연달아 돌려야 한다.** 시간 간격을 두면 코드가 같아도 다르게 나온다.
(셰이더·디노이저 캐시 재구축으로 보이나 메커니즘은 미확인.)

**② GPU 경합 시 초반 프레임이 미수렴 상태로 저장된다.**
Isaac 4개가 동시에 GPU를 잡은 상태에서 돌렸더니 285프레임에 **70분**(평소 16분)이 걸렸고,
**프레임 0~9가 조명이 안 올라온 채** 저장됐다(평균차 118/255, 밝기 95 vs 198). 10프레임부터는
정상 수준(0.7/255)으로 떨어진다. → **렌더는 한 번에 하나씩.**

**③ `simulation_app.close()`가 1시간 넘게 멈춘다.**
285프레임을 다 저장한 뒤에도 8 GB GPU를 계속 잡고 있었다. 이게 ②의 원인이 됐다.
→ **산출물이 다 나오면 PID로 kill.** `pkill -f "04_render_obs_isaac"` 는 **쓰지 말 것** —
그 문자열이 명령줄에 든 대기 셸까지 죽인다(실제로 다음 렌더 작업이 같이 사라졌다).
