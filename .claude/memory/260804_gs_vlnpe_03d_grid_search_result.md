# `03d_grid_search_params.py` — 8축 파라미터 그리드서치 결과

GT / 기준선ⓒ / 생성 경로 세 쌍의 거리(`d(GT,ⓒ)`, `d(GT,path)`, `d(ⓒ,path)`)를 8개 축에서
각각 독립적으로(다른 7개는 프로덕션 기본값에 고정) 그리드서치했다. **순수 탐색이며 00~03c의
기본값은 바꾸지 않았다.**

`d(ⓒ,path)`(기준선과 생성 경로 사이 거리)는 이번에 새로 추가한 지표다 — 생성 경로가
"이론적 최선"에서 얼마나 벗어났는지를 직접 보여준다.

## 실행

```
/workspace/isaaclab/_isaac_sim/python.sh scripts/dataset_converters/gs_vlnpe/03d_grid_search_params.py --num_episodes 20
```
20 에피소드 × 2씬 × 8축(51개 조합) = 57초. 출력: `gridsearch/results.json`,
`logs/gs-vlnpe/03d_grid_search_params/report.html`.

## 내장 회귀 검증 — 8중으로 통과

축 1·2·4·5·6·7의 "현재 기본값" 지점, 축3의 (connectivity=8, weight=0), 축8의 `any`는 전부
지금 프로덕션 03 설정과 정확히 같다. 그 지점에서 `d(GT,path)`가 이미 검증된 값(17DRP5sb8fy
0.103, s8pcmisQ38h 0.134)과 일치하는지 스크립트 안에서 자동 assert했다 — **9개 축 전부 통과**
(exit 0). `esdf_utils.astar()`에 추가한 `connectivity`/`clearance`/`clearance_weight` optional
인자가 기존 호출부(03/03b/03c)에 영향 없음도 재실행으로 재확인(수치 완전 불변).

## 새로 알게 된 것 3가지

**① `connectivity=4`가 실제 하드 충돌을 낸다.** 이전엔 "4-이웃이 Fréchet를 악화시킨다"까지만
알았는데, 이번에 처음으로 **장애물을 실제로 관통하는 사례**를 발견했다(17DRP5sb8fy, 1건).
스무드니스 문제가 아니라 안전 문제라는 게 이번 스윕의 새 정보다.

**② `d(ⓒ,path)`가 "refine = 정규화" 메커니즘을 수치로 직접 보여준다.** `refine_radius`를
0.05→0.4로 키우면:
```
d(GT,ⓒ)   0.054 → 0.190   (기준선이 GT에서 점점 멀어짐)
d(ⓒ,path) 0.136 → 0.043   (기준선과 생성 경로는 점점 같아짐)
```
반경이 커질수록 **기준선과 생성 경로가 서로 수렴**하면서 **둘 다 GT에서 멀어진다** — refine이
"GT에 맞추는" 동작이 아니라 "무엇이든 같은 형태로 정규화하는" 동작이라는 이전 결론(03c)을
숫자로 직접 확인한 것이다.

**③ `smooth_step`은 완전한 no-op이 아니다.** 처음으로 두 씬이 **같은 방향**으로 반응한 축이다
(작을수록 근소하게 낫다). 다만 효과가 1% 수준이라 현재 0.05를 바꿀 근거는 못 된다.

## 이미 알던 것의 재확인

- `h_nav`·`refine_radius`는 현재값이 최적(각각 이전 세션에서 이미 결론난 값).
- `r_b` 축소는 위험(하드충돌 폭증), 확대는 씬에 따라 갈림 — 0.25가 최선의 절충.
- `thin_waypoints` 간격은 chamfer-스무드니스 트레이드오프(이전에 문서화된 그대로).
- **`astar_cell_m`·`downsample_mode`에서 씬1/씬2가 다시 반대 방향으로 움직인다** — 이 세션
  내내 반복된 패턴이 8축 스윕에서도 그대로 나타난다. **전역 파라미터로는 더 못 줄인다는
  신호가 이번에도 확인됐다.** 2씬 40에피소드로는 이런 동전던지기를 가를 표본이 못 된다 —
  다음으로 의미 있는 건 파라미터를 더 만지는 게 아니라 **씬 수를 늘리는 것**이다.

## 구현 메모

- `esdf_utils.astar()`에 `connectivity`(기본 8)와 `clearance`/`clearance_weight`(기본
  `None`/`0.0`, 완전 no-op) optional 인자 추가. 시그니처 하위호환 — 03/03b/03c 무수정.
- self-check 게이트 10 → **11개** (`[1g/5]`: connectivity 4/8 차이, clearance bias no-op·효과).
- `clearance_weight`용 coarse clearance 배열은 `03d`의 로컬 `coarse_mean()`(ESDF를 factor배
  블록으로 평균 다운샘플)로 만든다 — 이 축 전용이라 `esdf_utils`에는 안 넣었다.
- `plan_variant()`가 03의 `plan_episode`와 완전히 같은 순서를 도므로, 기본값 지점에서
  비트 단위로 같은 결과가 나온다(회귀 검증이 성립하는 이유).
