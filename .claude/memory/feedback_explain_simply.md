사용자는 설명이 길고 복잡해질 때마다 "쉽게 설명해" / "이해가 잘 안됨"으로 여러 번 교정했고,
마지막에 "앞으로 이해하기 쉽고 명료하게 말해"로 상시 지시를 내렸다.

지켜야 할 것:
- **결론 먼저, 근거는 숫자로.** 과정·구조·내가 뭘 했는지는 묻지 않으면 말하지 않는다.
  ("구성을 나한테 보여줘봤자.. so what?")
- 리포트/보고는 **목적 / command와 결과 / takeaway** 세 조각만.
- 선택지를 나열하지 말고 **추천 하나**를 준다.
- 표는 비교할 게 2개 이상일 때만. 한 줄로 되는 건 한 줄로.

**Why:** 사용자는 결정을 내리려고 읽는다. 과정 서술은 결정에 안 쓰이므로 순수 노이즈다.

**How to apply:** 답변을 쓴 뒤 문단마다 "이게 사용자의 다음 행동을 바꾸나?"를 묻고,
아니면 지운다. [[feedback-language]] 와 함께 적용된다.
